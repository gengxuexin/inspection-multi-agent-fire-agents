# 精排调优 A/B 实录

> 这份文档记录三轮 A/B 的完整过程与结论。
> **重点不是最终结论，而是每一轮"改了什么、怎么验证、结果说明了什么"。**

---

## 一、方法

三轮都遵循同一套规则，否则结论不可信：

| 要素 | 固定为 | 说明 |
|------|--------|------|
| 索引 | 同一份 FAISS | 换 embedding 必须重建索引 |
| 样本 | `qa_samples.jsonl` 47 条 | 不增不减 |
| 模型 | 同一配置 | judge 模型的随机性是主要噪声源 |
| 变量 | **只切精排** | 不同时改分块/权重/阈值 |
| 噪声底 | ±0.05 | 实测抖动 0.021 的 2.4 倍 |
| 对比工具 | `--baseline` + 指纹 | 自动检空跑 |

执行脚本：`deploy/tools/ab_rerank.sh`

## 二、起点：v7/v8/v9 全是空跑

## 三、定位根因：三层，不是一层

### 第一层：覆盖率饱和

原实现 `if t in text` 是 bool 命中——命中 1 次和 5 次同权。
后果：10~32 个候选并列满分，BM25 把 P4 标准条目排到第 1 的判断被抹平。

### 第二层：IDF 被参数自己抹平（更根本）

`_IDF_MAX = 3.0`，而 log(4019) = 8.30：

| 词 | df | raw_idf | 截断后(MAX=3) |
|----|----|---------|----------------|
| 电线电缆（答案词）| 12 | 5.734 | **3.000** |
| 类产品 | 17 | 5.408 | **3.000** |
| 消防产品 | 108 | 3.607 | **3.000** |
| 属于（纯噪声）| 123 | 3.479 | **3.000** |

**df < 200 的词全压成同一个值。答案词和噪声词权重完全相同 ——
IDF 加权等于没加。**

### 第三层：tf 饱和方向反了

第一版改成 `idf * (1 + ln(1+tf))`，想奖励"命中多次"。结果排名大幅后退
（建筑消防设施 212 → 565）。

诊断发现噪声片段靠这个刷分：
```
tf = {'消防设施': 1, '包括': 7, '建筑': 4}
```
**法条文本里重复的往往是虚词。重复次数不是相关性的证据。**

## 四、第 1 轮 A/B：精排改动（`_IDF_MAX=8.0` + `idf²` + 疑问句折扣）

| 指标 | 旧精排 | 新精排 | 差值 | 判定 |
|------|--------|--------|------|------|
| faithfulness | 0.976 | 0.971 | -0.005 | 不可作结论 |
| answer_relevancy | 0.719 | 0.736 | +0.017 | 不可作结论 |
| context_precision | 0.209 | 0.230 | +0.021 | 不可作结论 |
| **context_recall** | 0.574 | **0.511** | **-0.063** | **可信：退化** |

指纹 `fe4dcfb5…` ≠ `711d7e02…` → 不是空跑。

### 分层定位

```
category   直查法条     n=20   0.700 → 0.750  (+0.050)
category   跨文档综合    n=21   0.524 → 0.381  (-0.143)
category   陷阱题       n= 6   0.333 → 0.167  (-0.167)
```

多条样本 1.00 → 0.00 且 `top1 未变` —— **答案还在候选池里，
只是被压出 top5**。

### 根因：疑问词折扣判据太粗

跨文档问题天然含疑问词：
> 「消防安全技术服务机构可以从事**哪些**业务？」

而旧判据按**个数**算占比 → `cue_ratio` 很高 → 被误判成"信号弱"而打折。
**可它恰恰是信号很强的复杂问题。**

**结论：不该上线。** 方向对（消除了饱和），但副作用伤到了更难的问题。

## 五、第 2 轮 A/B：B 方案（IDF 加权判据）

### 改动 1：判据从「个数占比」改为「IDF 加权占比」

```python
cue_ratio = sum(weights[t] for t in token_set if t in _QUERY_CUES) / total_w
```

**理由**：IDF 编码的正是"这个词有多稀有"。
真正没区分度的虚词（「吗」「呢」「的」）全库到处都是 → idf ≈ 0.15；
而罕见词即便属于疑问词集合，idf 也更高。

实测（4019 片段库）：

| 词 | df | idf |
|----|----|-----|
| 哪些 | 0 | 0.150 |
| 的 | 3495 | 0.150 |
| 吗 | 0 | 0.150 |
| 可以 | 664 | 1.799 |
| 包括 | 307 | 2.569 |
| 属于 | 123 | 3.479 |
| 包含 | 42 | **4.538** |

### 改动 2：剔除被误收进集合的实词

量完 idf 才发现第一版集合里有三个**实词**：

| 词 | idf | 判定 |
|----|-----|------|
| 包含 | 4.538 | 实词，**最该定位答案**，却被打折 |
| 属于 | 3.479 | 实词 |
| 包括 | 2.569 | 实义动词 |

> **教训：写停用词表不能凭语感判断"像不像虚词"，得拿真实语料量 idf。**
> 高频且 idf≈下限 → 真虚词，可打折；idf > 2 → 是实词，打折伤召回。

关于「包括」保留在 `_TIER_TABLE_CUES` 但从 `_QUERY_CUES` 移除：
它在噪声片段里高频出现确实是个问题，但那应该靠**改分块**解决，
不是在打分函数里惩罚它。

### 判据验证（确定性，先于评测）

| 查询 | 类型 | 旧 | 新 |
|------|------|-----|-----|
| 消防安全技术服务机构可以从事哪些业务？ | 跨文档综合 | 0.222 | **0.080** |
| 消防安全重点单位有哪些消防安全义务？ | 跨文档综合 | 0.143 | **0.008** |
| 消防产品的认证目录包含哪些类别？ | 陷阱题 | 0.250 | **0.010** |
| 建筑消防设施包括哪些 | 对照 | 0.250 | **0.020** |
| 电线电缆类产品属于消防产品吗 | 对照 | 0.200 | **0.008** |

全部降到 0.08 以下。36 个现有单测全通过。

## 六、第 2 轮 A/B 结果：B 方案无效，且暴露了一个方法论错误

### 结果：与方案 A 逐位相同

| 指标 | 旧精排 | 方案 A | 方案 B |
|------|--------|--------|--------|
| faithfulness | 0.976 | 0.971 | 0.983 |
| answer_relevancy | 0.719 | 0.736 | 0.728 |
| context_precision | 0.209 | 0.230 | 0.226 |
| **context_recall** | 0.574 | **0.511** | **0.511** |

**recall 仍是 0.511，与方案 A 完全相同。分层数字也逐位相同**：

```
跨文档综合   0.524 → 0.381  (-0.143)
陷阱题      0.333 → 0.167  (-0.167)
```

### 这个结果本身比数字更有价值

方案 B 改的正是疑问词折扣（判据从个数占比改成 IDF 加权、
并剔除被误收进集合的实词「包含/包括/属于」）。
机制验证也确认判据生效了（跨文档类 cue_ratio 从 0.222 降到 0.080）。

**改了却毫无影响 → 说明诊断错了方向。**

如果当时不看分层数据、只看总数 -0.063，会得出
"方案 B 方向对但幅度不够，再调调折扣参数"的结论，
然后继续在错误的地方花时间。

## 七、真正的根因：我的 A/B 变量隔离是失败的

### 排查过程

**第 1 步：排除覆盖率信号本身**

构造 4 个变体，只用覆盖率打分（不含结构匹配/长度惩罚），
看目标片段排名：

| 变体 | top5 内 | 中位排名 |
|------|---------|---------|
| V0 旧（idf≤3, 线性, bool）| 6/6 | 1 |
| V1 只放宽到 8（线性, bool）| 6/6 | 1 |
| V2 只用平方（idf≤3）| 6/6 | 1 |
| V3 新精排（idf≤8, 平方）| 6/6 | 2 |

**全部 6/6 都能排进 top5。** 纯覆盖率信号不会导致 recall 归零。

**第 2 步：查候选池是否变了**

```
top5 完全相同   8/47  (17%)
部分相同      26/47  (55%)
集合大变      13/47  (28%)
```

只有 17% 的样本候选集没变 —— **召回阶段就变了**。

### 根因

`_IDF_MAX` 是 `HybridRetriever` 的**类属性**，而 `self._idf`
在 `__init__` 里构建 BM25 时就定型了：

```python
# 第 283 行（BM25 构建）
self._idf = {
    w: min(self._IDF_MAX, ...)      # ← BM25 用
}

# 第 461 行（精排）
weights = {t: self._idf.get(t, default_idf) for t in token_set}   # ← 精排复用同一份
```

**我改 `_IDF_MAX: 3.0 → 8.0` 时，同时改了 BM25 召回与精排排序两处。**

而 A/B 脚本里写的"只切精排这一个变量"是**错的**。

### 修法：拆成两个独立参数

```python
_IDF_MAX_BM25   = 3.0     # BM25 召回：保持原值，不扰动已验证的召回
_IDF_MAX_RERANK = 8.0     # 精排覆盖率：放宽
```

精排不再复用 BM25 的 idf 字典，而是自己从 `self._df` / `self._n_docs` 计算。
同时保留 `_df` 与 `_n_docs` 两个原始字段（不从头截断后的 idf 反推）。

测试也要改：mock 里补 `_df` / `_n_docs`。
**没有给产品代码加兼容别名** —— 加了别名会让测试验证不到真实路径，
拆分的意义（区分 BM25 与精排）就丢了。

## 八、本轮最重要的一条教训

> **「改一个常量」不等于「改一个变量」。**

我一直在用"只改精排覆盖率"来描述这轮 A/B，
但 `_IDF_MAX` 的作用域覆盖了 BM25 与精排两处 ——
**变量隔离从一开始就是假的。**

这个错误有隐蔽性：

1. 代码上确实只改了一行常量，看起来像单变量
2. 常量的名字（`_IDF_MAX`）也没暗示它被两处使用
3. 改完之后单测全通过、机制验证也通过
4. 甚至跑出了"precision 上升"这种看起来合理的结果

**只有做候选池重叠度分析才会暴露它。**

### 可推广的做法

调参时遇到共享的可配置项，先确认作用域：

```bash
grep -rn '_IDF_MAX' agent1/ tests/ gateway.py common/
```

看它被几处引用。**如果超过一处，就不是单变量实验。**

## 九、最终结论：三轮 A/B 的完整记录

| 轮次 | 改动 | 指纹重叠 | precision | recall | 判定 |
|------|------|---------|-----------|--------|------|
| 历史 v7/v8/v9 | — | 100% | — | — | **空跑** |
| 第1 轮 A | idf≤8 + idf² + 疑问词折扣 | 17% | +0.021 | **-0.063** | 退化 |
| 第 2 轮 B | + IDF加权判据 + 剔除实词 | — | +0.017 | **-0.063** | 无变化 |
| 第 3 轮 C | 拆分 IDF 上限（BM25 3.0 / 精排 8.0）| 19% | +0.029 | **-0.085** | 退化加剧 |

**三轮都没有改善 recall。**

### 最终根因：不是 bug，是取舍

第 3 轮拆分后 BM25 的 idf 已还原成 3.0，候选池仍大变（重叠仅 19%）——
说明**变化确实来自精排本身**，我最初"BM25 被牵连"的猜测是错的
（虽然那个发现本身有价值：它教会我共享常量会破坏变量隔离）。

再看 5 条退化样本，全是「跨文档综合 / 程序义务」类：

```
[ 5] 消防技术服务机构从业条件是什么？          top5 重叠 2/5
[12] 消防安全技术机构可以从事哪些业务？        top5 重叠 3/5
[20] 消防执法全过程记录制度要求记录哪些内容？  top5 重叠 2/5
[24] 消防技术文书应当使用什么式样？            top5 重叠 2/5
[27] 消防安全重点单位有哪些消防安全义务？      top5 重叠 1/5
```

**机制**：`idf²` 超线性加成让「单词命中」拿到极高权重，
于是命中 1 个稀有词的片段压过命中 2-3 个常见词的片段。

- **直查法条** 问的是单文档里的某一条 → 单词命中正是对的 → recall +0.050
- **跨文档综合** 答案横跨多份文件 → 每份片段都只命中 1 个词 → 全部被压下去

**这不是缺陷，是我该承认的取舍。** `idf²` 优化的是"找准那一条"，
代价是"找齐那几条"。而当前样本里跨文档类占 21/47（45%），代价大于收益。

### 决策：不上线，回退到旧精排

保留的成果：

| 项 | 状态 |
|----|------|
| `_IDF_MAX` 拆成 BM25/RERANK 两个 | **保留** —— 结构上正确，且让后续实验能真正做变量隔离 |
| `_QUERY_CUES` 剔除「包含/包括/属于」 | **保留** —— 那三个确实是实词，idf 4.5/2.6/3.5 |
| `idf²` 超线性加成 | **回退** —— 代价超过收益 |
| 疑问词折扣（B 方案判据） | **回退** —— 对结果无影响，且增加了复杂度 |

回退后 BM25 与精排都用 3.0，等价于旧行为，但代码结构更清晰、
后续调参不会再出现"改一个常量动了两处"的问题。

### 如果将来还要优化跨文档 recall

按优先级：

1. **加一条跨文档信号**：识别需要多源汇总的查询
   （`category == "跨文档综合"` 已有标注，可作为训练信号），
   对这类查询降低 `idf²` 的陡度、改为线性。

2. **改 top_k 再评估**：recall 天花板受 top_k 限制。
   跨文档类答案分散，top_k=5 可能天然不够。
   **但这会让 RAG 上下文变长、挤占生成预算**，要一起算账。

3. **先扩样本再动手**：47 条里跨文档类 21 条，
   单类差值的标准误约 0.10，比噪声底还大一倍。
   **现在调这个参数，测的是噪声不是信号。**

第 3 条最重要 —— 前两条在样本量足够之前做，等于继续在噪声里调参。


## 十、方法层面的四条收获

### 1. 一次 A/B 只能回答"有没有用"，回答不了"为什么"

第 1 轮发现 recall 退化后，分层统计（按 category / difficulty）
才指出是"跨文档综合"和"陷阱题"受损。
没有分层，就只能看到总数下降，然后瞎调参数。

### 2. "消除了饱和"不等于"效果变好"

第 1 轮确实消除了覆盖率饱和（并列从 10/32 降到 1），
机制上是对的。但 precision 涨的那部分来自"直查法条"，
同时伤害了更难的题型 —— **净效果是负的**。

**机制正确 ≠ 整体正确。** 局部改进必须有全局度量兜底。

### 3. 先用确定性方法验证方向，再花时间跑评测

第 2 轮改判据后，先算了一遍 cue_ratio（3 秒），
确认跨文档类从 0.222 降到 0.080，才值得花 5 分钟跑 RAGAS。

**反过来说：如果只跑评测，5 分钟后才发现判据没生效，
那 5 分钟就白花了。**

## 十一、还没解决的

1. **样本量偏小**：47 条，单指标差值的标准误在 0.03 量级，
   比噪声底还大。当前机制能检出空跑，**检不出小效应**。
   要检出 0.02 量级的真实提升，需要 200+ 条或多次重复取平均。

2. **LLM judge 随机性没消除**：根治要同一份 contexts 打分 3 次取平均
   （成本 3 倍），或换更强的 judge。都没做。

3. **没有分层统计进正式报告**：现在要单独跑诊断脚本才能看到
   category/difficulty 的分解。应该直接进报告。

4. **弃答样本未单独统计**：合理弃答与过度保守在总分里表现一样，
   但业务后果完全不同。

5. **「包括」在噪声里高频的根因在分块**，没解决 ——
   靠改分块（避免这类词出现在随机位置）比改打分函数更治本。
